The service is split into four independent Gradle modules with a one-way dependency direction: `j-store-fulfillment-domain` defines the FulfillmentOrder aggregate, its state machine, errors, events, and the repository interface; `j-store-fulfillment-infrastructure` implements that repository with Spring Data JPA entities (FulfillmentOrderPO) backed by PostgreSQL; `j-store-fulfillment-application` orchestrates use cases through FulfillmentUseCase/FulfillmentApplicationService and translates integration messages into domain mutations; `j-store-fulfillment-boot` wires all layers as a Spring Boot application, exposing a REST controller and applying transactional boundaries around use-case calls. The domain layer remains framework-free, and the boot layer depends on application + infrastructure while the application layer depends only on domain — enforcing clean separation of concerns across module boundaries.
