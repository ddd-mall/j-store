The module is organized as four sibling Gradle projects with a strict unidirectional dependency: `j-store-fulfillment-domain` owns the FulfillmentOrder aggregate, state machine, errors, events, and the repository interface; `j-store-fulfillment-infrastructure` implements that interface via Spring Data JPA POs against PostgreSQL; `j-store-fulfillment-application` contains use cases (`FulfillmentUseCase`/`FulfillmentApplicationService`) and an integration message handler that translate inbound commands into domain mutations; `j-store-fulfillment-boot` is the Spring Boot entry point that wires all layers, exposes a REST controller, and applies transactional boundaries around use-case calls. The domain layer has no framework dependencies, so it can be tested in isolation, while the boot layer depends on application + infrastructure and the application layer depends only on domain — this enforces clean separation of concerns across module boundaries.
