The service is split into four Gradle subprojects with a strict one-way dependency direction: `j-store-payment-domain` owns the `PaymentOrder` aggregate, repository interface, and domain events; `j-store-payment-application` depends only on the domain to implement use cases (`PaymentUseCase`) and integration message handlers; `j-store-payment-infrastructure` implements the domain's `PaymentOrderRepository` via Spring Data JPA against PostgreSQL; `j-store-payment-boot` is the sole Spring Boot entry point that wires all layers, exposes `PaymentController`, and wraps use-case calls in transactions. Cross-module communication flows exclusively through the domain repository interface and domain events, keeping infrastructure decoupled from application logic and the boot layer free of business rules.
