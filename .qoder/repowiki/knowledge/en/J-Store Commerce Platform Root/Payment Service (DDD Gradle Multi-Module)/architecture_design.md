The module is split into four Gradle subprojects with a rigid dependency direction: `j-store-payment-domain` owns the `PaymentOrder` aggregate, repository interface, value objects, errors, and domain events; `j-store-payment-application` depends only on the domain to implement the `PaymentUseCase` interface and integration command handlers; `j-store-payment-infrastructure` implements the domain's `PaymentOrderRepository` via Spring Data JPA against PostgreSQL; `j-store-payment-boot` is the sole Spring Boot entry point that wires all layers, exposes `PaymentController`, and provides a `TransactionalPaymentUseCase` decorator around the application service. Cross-module communication flows exclusively through the domain repository interface and domain events published via `DomainEventPublisher`, keeping infrastructure decoupled from application logic and the boot layer free of business rules. The boot configuration registers beans for the application service, transactional use-case wrapper, and command handlers, making it the single composition root.
