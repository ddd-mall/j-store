Two Gradle subprojects form a clean DDD boundary:
- `j-store-shop` holds pure Kotlin domain code: the `Merchant` and `MerchantMembership` aggregates extending `AggregateRoot`, their value types (`MerchantId`, `MerchantRole`, `MerchantStatus`), error definitions, and repository interfaces (`MerchantRepository`, `MerchantMembershipRepository`) that extend `AggregateRepository`. The `MerchantService` orchestrates use cases (create, list, add/change/disable members) using `fun interface` ports (`MerchantIdGenerator`, `UserAccountLookup`) for external dependencies, and delegates authorization to an internal `MerchantAuthorizationService`.
- `j-store-shop-infrastructure` depends on `:j-store-shop` via `api(project(":j-store-shop"))` and provides Spring Boot + JPA implementations: PO entities (`MerchantPO`, `MerchantMembershipPO`) annotated with `@Entity`/`@Table`, Spring Data repositories (`MerchantPOJpaRepository`, `MerchantMembershipPOJpaRepository`), and `@Repository` classes (`MerchantRepositoryImpl`, `MerchantMembershipRepositoryImpl`) that convert between domain objects and POs through internal `Converter` objects. Each repository method is wrapped in `@Transactional` or `@Transactional(readOnly = true)`.
- Dependency direction is strictly one-way: infrastructure → shop domain; the domain layer has no framework imports.
