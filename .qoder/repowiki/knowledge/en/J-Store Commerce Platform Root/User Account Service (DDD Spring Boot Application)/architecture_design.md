The module follows a layered DDD split across four Gradle subprojects with strict dependency direction: `j-store-user-domain` defines pure Kotlin aggregates, value objects, repository/infrastructure ports, and domain events; `j-store-user-infrastructure` implements those ports via JPA (`UserAccountPOJpaRepository`), BCrypt hashing, HS256 JWT issuance, and Redis-backed login attempt guarding and phone verification; `j-store-user-application` holds stateless use-case classes (`UserAccountService`, `UserAccountUseCase`) that orchestinate domain calls; `j-store-user-boot` is the Spring Boot entry point that wires everything in `UserBootConfiguration` by declaring `@Bean`s for each port implementation (e.g. `BCryptPasswordHasher`, `JwtTokenProvider`, `RedisTokenStore`, `RedisLoginAttemptGuard`, `RedisPhoneVerificationGateway`) and injecting them into the application-layer `UserAccountService`, which is then wrapped by `TransactionalUserAccountUseCase` to provide transactional boundaries using Spring's `PlatformTransactionManager`. Controllers in `user_boot/controller` depend only on the application layer, keeping persistence and security concerns out of the web boundary.
