The module implements the application layer of the Fulfillment service with three Kotlin files in `com.jstore.fulfillment.service`. `FulfillmentUseCase` declares the use-case API (create, read, prepare, dispatch, deliver). `FulfillmentApplicationService` is the sole concrete implementation, depending on `FulfillmentOrderRepository`, `SnowFlakSequence` (for ID generation), and `DomainEventPublisher` to publish pending events after mutations. A private `mutate(orderId) { operation }` helper centralizes load-mutate-save-event-publish flow for state-changing operations. `FulfillmentIntegrationMessageHandler` defines `CreateFulfillmentForOrderCommandHandler`, which adapts inbound `CreateFulfillmentForOrderCommand` messages from `j-store-integration-contracts` into the internal `FulfillmentRequest` DTO and delegates to the use case via the `IntegrationMessageHandler<T>` contract. Dependency direction is strictly inward: this layer depends only on `:j-store-fulfillment-domain` and shared infrastructure `:j-store-common-core`, keeping persistence and messaging concerns out of the domain.
