The module is split into four Gradle subprojects that follow a clean-layered DDD pattern: `accounting_domain` owns the core entities (LedgerAccount, JournalEntry, AccountingPeriod, SettlementStatement) and repository interfaces; `accounting_infrastructure` implements those repositories via Spring Data JPA with PO/POJpaRepository pairs per aggregate; `accounting_application` provides use cases and event handlers that orchestrate domain operations; `accounting_boot` wires everything together in Spring configuration. Cross-boundary data flows from external systems through ACL services in the domain layer, while events (JournalEntryPosted, JournalEntryReversed, SettlementConfirmed, SettlementPaid) propagate between application and domain layers. Each aggregate follows a consistent pattern: an interface + impl pair in domain, a PO + JpaRepository in infrastructure, and a RepositoryImpl bridging them.
