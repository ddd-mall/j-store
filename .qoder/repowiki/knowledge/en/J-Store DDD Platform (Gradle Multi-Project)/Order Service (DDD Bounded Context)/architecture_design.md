The service is organized as a classic layered DDD module split across four Gradle subprojects. The `j-store-order-domain` defines the Order and AfterSale aggregate roots, value objects, repository interfaces, and ACL contracts (e.g. GoodsService) with no framework dependencies. `j-store-order-application` orchestrates these aggregates through use-case classes (`OrderUseCases`, `AfterSaleApplicationService`) and publishes domain events via an event bus. `j-store-order-infrastructure` implements the repository interfaces with Spring Data JPA entities/POs and provides the GoodsService adapter; it also hosts integration tests against embedded PostgreSQL. `j-store-order-boot` wires everything via Spring configuration (`OrderBootConfiguration`, `TransactionalOrderUseCases`, `RedisConfig`), exposes REST endpoints through `OrderController` and `AfterSaleController`, and registers message handlers for cross-context events. Dependencies flow strictly downward: boot → application + infrastructure → domain, keeping the domain layer free of framework concerns.
