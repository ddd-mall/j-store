This is a thin Spring Boot configuration layer (Kotlin `@Configuration` beans) that assembles the goods feature from its subprojects: `j-store-goods-domain`, `j-store-goods-application`, `j-store-goods-infrastructure`, `j-store-goods-api`, plus shared `j-store-common-*` and `j-store-integration-contracts`. `GoodsBootConfiguration` registers factory beans (`SpuFactory`, `GoodsStyleFactory`, `SpuSnapshotFactory`) built with a `SnowFlakSequence`, and composes `CommodityService` from those factories plus repositories and a `DomainEventPublisher`. Two transactional adapter classes — `TransactionalCommodityUseCase` and `TransactionalInventoryUseCase` — wrap their respective `*UseCase` interfaces with programmatic `PlatformTransactionManager`/`TransactionTemplate` boundaries: write operations run in a default read-write template, while snapshot queries run in a read-only template. The module depends only on the other goods modules and Spring Boot starters; it contains no business logic beyond bean wiring and transaction demarcation.
