The module enforces a strict one-way layered dependency: `j-store-goods-domain` defines aggregates (SPU/SKU/GoodsStyle), repository interfaces, factories, snapshots and events; `j-store-goods-application` depends only on those domain interfaces to implement use cases (`CommodityUseCase`, `InventoryUseCase`) and event handlers; `j-store-goods-infrastructure` implements the domain repository interfaces via Spring Data JPA POs under `persistence/`; `j-store-goods-boot` is the Spring `@Configuration` entry point that wires factories (`SpuFactory`, `GoodsStyleFactory`, `SpuSnapshotFactory`), domain services, and exposes `TransactionalCommodityUseCase` / `TransactionalInventoryUseCase` as `@Primary` beans so application-layer use cases execute inside transactions; `j-store-goods-api` publishes only the read-side snapshot query interface (`GoodsSnapshotQueryService`) consumed by other services. Cross-child communication is strictly unidirectional — application and infrastructure depend on domain interfaces, never the reverse — keeping the feature self-contained and testable in isolation.
