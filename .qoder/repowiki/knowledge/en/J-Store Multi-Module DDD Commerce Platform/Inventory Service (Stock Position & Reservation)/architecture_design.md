Organized as a four-layer DDD module with strict dependency direction: `j-store-inventory-domain` owns pure aggregates (`StockPosition`, `StockReservation`) and repository/guard interfaces (`StockPositionRepository`, `StockReservationRepository`, `StockPositionGuard`); `j-store-inventory-application` implements the `InventoryUseCase` orchestration in `InventoryService` plus command handlers (`ReserveInventoryCommandHandler`, `ConfirmInventoryCommandHandler`, `ReleaseInventoryCommandHandler`, `PhysicalStockChangedHandler`) that translate inbound messages from `j-store-integration-contracts` into use-case calls and publish domain events via `DomainEventPublisher`; `j-store-inventory-infrastructure` provides Spring `@Repository` implementations of the domain repositories backed by Spring Data JPA (`StockPositionPOJpaRepository`, `StockReservationPOJpaRepository`) with pessimistic-write locking for concurrency; `j-store-inventory-boot` wires beans in `InventoryBootConfiguration`, wrapping each handler in a `TransactionTemplate` so message handling runs within a mandatory transaction. The application layer depends only on domain interfaces, keeping persistence and messaging concerns out of the core business logic.
