This module is the infrastructure layer of the order service. It depends on `:j-store-order-domain` (via `api`) and `:j-store-goods-api` (via `implementation`), and exposes three top-level packages:
- `domain.order` and `domain.aftersale` each contain a `@Repository` implementation (`OrderRepositoryImpl`, `AfterSaleRepositoryImpl`) that implements the domain `*Repository` interface and delegates all persistence to Spring Data JPA repositories under a `persistence/` subpackage. Each subpackage holds Jakarta `@Entity` PO classes (`OrderPO`, `OrderItemPO`, `OrderRefundFactPO`, `AfterSalePO`, `AfterSaleItemPO`, `AfterSaleCapacityPO`, `AfterSaleCommandReceiptPO`), corresponding `*JpaRepository` interfaces, and custom `@Converter`s (`RecipientInfoPOConverter`, `I18nGeoAddressConverter`) for JSONB columns.
- `acl/GoodsServiceImpl` adapts the external `GoodsSnapshotQueryService` to the local `GoodsService` interface, translating SPU/SKU snapshots into `GoodsInfo`.

Dependency direction is strictly inward: this module depends on domain interfaces only; PO types never leak outside the repository implementations via internal `Converter` objects or private `toPO`/`toDomain` functions. Transaction boundaries are enforced with `@Transactional(propagation = Propagation.MANDATORY)` on write methods so callers must supply an existing transaction. Concurrency control combines optimistic locking (`@Version`) with explicit row-level locking via `SELECT ... FOR UPDATE` in sorted order over item IDs to prevent deadlocks. Idempotency is enforced through a dedicated `after_sale_command_receipts` table with a unique constraint on `(actor_id, command_type, idempotency_key)`, checked via a try-insert pattern before mutating state.
