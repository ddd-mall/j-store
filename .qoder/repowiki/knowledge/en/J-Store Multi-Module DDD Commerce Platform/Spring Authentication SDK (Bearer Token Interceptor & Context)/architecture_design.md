The module is a Spring Boot auto-configuration library organized into four sibling packages with a strict one-way dependency direction:
- `annotation/` — runtime-only markers (`@RequireLogin`, `@SkipLogin`, `@CurrentUserId`) consumed by the interceptor and argument resolver.
- `context/` — per-request state via a singleton `object AuthenticatedUserContext` wrapping a `ThreadLocal<UserId>` plus an `AuthenticationException`; depends only on `j-store-user-domain.UserId`.
- `error/` — centralized `AuthenticationErrors` object mapping failure cases to `BusinessError` entries (code, message, HTTP status) used uniformly by the interceptor.
- `spring/` — integration layer: `AuthenticationAutoConfiguration` declares beans gated by `@ConditionalOnBean(TokenProvider, TokenStore)` and `@ConditionalOnWebApplication(SERVLET)`, registers `AuthenticationInterceptor` on `/**`, and exposes `CurrentUserIdArgumentResolver`. The interceptor implements `HandlerInterceptor.preHandle` to extract the `Authorization: Bearer ...` header, call `TokenProvider.parseAccessToken` and `TokenStore.isSessionActive`, set the context, and write JSON error responses; `afterCompletion` clears the thread-local. Path-based policy is extensible through the `AuthenticationConfigurer` interface (default empty lists), allowing consumers to declare `authenticatedPathPatterns()` and `excludedPathPatterns()`.
- Auto-activation is declared in `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` so no manual wiring is needed.
Dependency direction is strictly inward: `spring/` → `config/`, `context/`, `annotation/`, `error/`; `context/` and `error/` have no intra-module dependencies beyond `user.domain.UserId`.
