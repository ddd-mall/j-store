Two independent Gradle sub-projects under a shared `com.jstore` group: `j-store-warehouse` provides a minimal JVM `Main.kt` entry point, while `j-store-warehouse-infrastructure` implements persistence via Spring Boot. The infrastructure module declares an `api` dependency on `:j-store-warehouse-domain`, importing domain types (`PhysicalStock`, `PhysicalStockId`) from that sibling module and implementing them through `PhysicalStockRepositoryImpl`. Persistence is modeled as a classic DDD boundary: a JPA entity `PhysicalStockPO` mapped to table `warehouse_physical_stock` with optimistic locking via `@Version`, exposed through a Spring Data `JpaRepository<PhysicalStockPO, String>` interface, and adapted to domain objects by private `toPO`/`toDomain` converters in the repository implementation. The repository method `save` is wrapped in `@Transactional(propagation = Propagation.MANDATORY)` to enforce transactional boundaries. No build-time dependency exists between `j-store-warehouse` and `j-store-warehouse-infrastructure`; they are currently decoupled artifacts.
