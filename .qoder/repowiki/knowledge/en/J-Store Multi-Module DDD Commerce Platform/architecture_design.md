The root Gradle build declares ~40 subprojects in `settings.gradle.kts`, grouping each bounded context (order, goods, user, shop, accounting, payment, fulfillment, inventory, warehouse) into a uniform four-layer split of domain/application/infrastructure/boot plus an API contract module, all sharing two foundational layers: `j-store-common-core` (DDD primitives, Result type, outbox contracts, geocoding) and `j-store-common-spring` (auto-configured outbox, domain/integration event buses). Cross-context communication is enforced via the shared `j-store-integration-contracts` module rather than direct service calls. The root `build.gradle.kts` centralizes Java 25 toolchain, Spotless formatting (ktfmt/google-java-format), CycloneDX BOM generation, and pre-commit/pre-push git hooks; `docker-compose.postgres.yml` provisions PostgreSQL 16 with numbered SQL migrations from `docker_infra`. A single orchestrator boot (`orchestration_boot`) wires together the assembled contexts to expose REST APIs and scheduled jobs backed by transactional outbox events.
