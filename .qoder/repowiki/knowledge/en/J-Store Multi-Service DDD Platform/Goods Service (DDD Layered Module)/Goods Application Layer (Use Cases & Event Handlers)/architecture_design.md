The module implements Clean Architecture application services under `com.jstore.goods.service`. Two primary use-case interfaces define the public ports: `CommodityUseCase` (SPU/SKU lifecycle, draft workflow, goods style) implemented by `CommodityService`, and `InventoryUseCase` (reserve/confirm/release/add) implemented by `InventoryService`. Both services depend on domain factories, repositories, and shared infrastructure (`DomainEventPublisher`, `InventoryLock`, `SnowFlakSequence`) from `j-store-common-core` and contracts from `j-store-integration-contracts`. Four `IntegrationMessageHandler` implementations bridge external messages to the use cases: `InventoryReservationEventHandler` (reserves stock with rollback), `InventoryConfirmEventHandler` (converts pre-reserve to deduct), `InventoryReleaseEventHandler` (releases reserved stock), and `AfterSaleStockRestoreEventHandler` (restores stock on refund). `CommodityService` additionally implements `GoodsSnapshotQueryService` from the API layer, making it the single entry point for both command and read operations. Dependency direction is strictly inward: application → domain + common + integration contracts; no cross-dependency between commodity and inventory except through shared infrastructure.
