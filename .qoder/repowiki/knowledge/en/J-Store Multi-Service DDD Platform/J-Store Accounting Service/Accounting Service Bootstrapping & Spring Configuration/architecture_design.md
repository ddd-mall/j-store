This module is a thin Spring Boot wiring layer with no business logic. `AccountingBootConfiguration` declares all Spring `@Bean`s: it constructs `AccountingApplicationService`, `SettlementApplicationService`, an anonymous `AccountingOrderService` adapter over `OrderRepository`, and four event handlers (`PaymentCapturedAccountingEventHandler`, `OrderCompletedAccountingEventHandler`, `PaymentRefundSucceededAccountingEventHandler`, `SettlementPaidAccountingEventHandler`). Transactional boundaries are provided by two decorator classes in `TransactionalAccountingUseCases.kt` — `TransactionalAccountingUseCase` and `TransactionalSettlementUseCase` — which wrap the underlying `AccountingUseCase`/`SettlementUseCase` via `TransactionTemplate` (read-only for queries, write for mutations) and are registered as `@Primary` beans so callers always get the transactional variant. Dependencies flow inward only to `j-store-accounting-domain`, `j-store-accounting-application`, `j-store-accounting-infrastructure`, plus shared order/domain and common-spring modules; there is no outward dependency on other application layers.
