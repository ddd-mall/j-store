The service follows a strict four-layer DDD split across sibling Gradle modules: `j-store-fulfillment-domain` owns the aggregate (FulfillmentOrder), its state machine, errors, events, and repository interface; `j-store-fulfillment-infrastructure` implements that repository with Spring Data JPA entities (FulfillmentOrderPO) and a JpaRepository; `j-store-fulfillment-application` orchestrates use cases and translates integration messages into domain mutations; `j-store-fulfillment-boot` wires everything together as a Spring Boot app, exposing a REST controller and applying transactional boundaries around use-case calls. Dependency direction is one-way: boot → application → infrastructure → domain, so the domain layer remains free of framework concerns.
