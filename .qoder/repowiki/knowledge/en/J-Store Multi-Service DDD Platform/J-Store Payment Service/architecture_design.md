The service follows a layered DDD split across four Gradle modules with strict dependency direction: `j-store-payment-domain` declares the `PaymentOrder` aggregate, repository interface, and domain events; `j-store-payment-application` depends only on the domain (plus shared contracts) to implement use cases and integration message handlers; `j-store-payment-infrastructure` implements the domain's `PaymentOrderRepository` via Spring Data JPA against PostgreSQL; `j-store-payment-boot` is the Spring Boot entry point that wires all layers, exposes a `PaymentController`, and wraps use-case calls in transactions. The boot module is the only one depending on Spring Web/Boot starters, while infrastructure adds JPA and an embedded Postgres for tests. Cross-module communication flows through the domain repository interface and domain events, keeping infrastructure and application decoupled from each other.
