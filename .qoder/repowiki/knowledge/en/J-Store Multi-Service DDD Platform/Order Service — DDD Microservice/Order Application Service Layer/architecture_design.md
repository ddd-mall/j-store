The module implements the application layer of a DDD-based order service. It defines two stable inbound-port interfaces — `OrderUseCase` and `AfterSaleUseCase` in `OrderUseCases.kt` — which are implemented by `OrderService` and `AfterSaleApplicationService`. Each use case follows a uniform pattern: load the aggregate via a repository, invoke domain behavior on the aggregate, persist with `orderRepository.save`, then publish pending domain events via `publishPendingEvents(domainEventPublisher)`. Cross-cutting concerns like idempotency (SHA-256 hashed receipts stored through `AfterSaleCommandReceipt`) and allocation actions (`AllocationAction.APPROVE`/`RELEASE`) are handled inside the application service before delegating to the domain. Integration boundaries are expressed as `IntegrationMessageHandler` implementations in `CommerceIntegrationMessageHandlers.kt`, `OrderStockEventHandler.kt`, and `OrderStockInsufficientEventHandler.kt`, each mapping an external contract event from `j-store-integration-contracts` into a use-case call. Dependency direction is strictly inward: this layer depends only on `j-store-order-domain`, `j-store-common-core`, and `j-store-integration-contracts`; it never depends on infrastructure or transport details.
