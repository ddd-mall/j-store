This module is the infrastructure layer of the order service, implementing domain interfaces from `:j-store-order-domain` and depending on `:j-store-goods-api`. It is organized into three top-level packages:
- `domain.order` and `domain.aftersale` each contain a Repository implementation (`OrderRepositoryImpl`, `AfterSaleRepositoryImpl`) plus a `persistence/` subpackage with JPA `@Entity` PO classes, `*JpaRepository` Spring Data interfaces, and custom `@Converter`s (e.g. `RecipientInfoPOConverter`, `I18nGeoAddressConverter`).
- `acl/GoodsServiceImpl` adapts the external `GoodsSnapshotQueryService` to the local `GoodsService` interface.

Persistence uses Spring Data JPA with Jakarta annotations; entities are mapped to tables `orders`, `order_items`, `order_refund_facts`, `after_sales`, `after_sale_items`, `after_sale_capacities`, and `after_sale_command_receipts`. Concurrency control combines optimistic locking (`@Version`) with explicit row-level locking via `SELECT ... FOR UPDATE` in capacity operations. Transaction boundaries are enforced with `@Transactional(propagation = Propagation.MANDATORY)` on write methods. Domain↔PO mapping is centralized in internal `Converter` objects or inline `toPO`/`toDomain` functions inside each repository implementation, keeping the boundary between domain and persistence explicit. Tests under `src/test/kotlin` include unit property tests, round-trip tests, and an integration test using `io.zonky.test:embedded-postgres` to validate concurrent reservation, idempotency receipts, and rollback semantics.
