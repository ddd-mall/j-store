The module follows a strict four-layer DDD split with unidirectional dependencies: `j-store-user-boot` (Spring Boot entry) depends on application + infrastructure, `j-store-user-application` depends only on domain, and `j-store-user-infrastructure` implements domain interfaces. Cross-layer wiring is centralized in `UserBootConfiguration`, which registers beans for `UserAccountFactory`, `PasswordHasher`, `TokenProvider`, `TokenStore`, `UserAccountRepository`, and the transactional `TransactionalUserAccountUseCase` that wraps `UserAccountService`. The domain layer exposes pure Kotlin contracts (`UserAccount`, `UserId`, `Nickname`, `Password`, repository/event interfaces); infrastructure provides concrete implementations via Spring Data JPA (PostgreSQL), Redis, BCrypt, and HS256 JWT; application layer composes these into use-case operations returning `Result<UserAccount, BusinessError>`; boot layer exposes REST endpoints under `/api/users` and injects a `JwtAuthenticationFilter` for all `/api/*` requests. Domain events are published through the shared `DomainEventPublisher` from `com.jstore.common.framework.event`.
