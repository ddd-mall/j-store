The module follows a layered DDD layout under `com.jstore.goods`:
- `domain/commodity`: core aggregates (`Spu`, `Sku`, `GoodsStyle`) with value objects (`Attribute`, `SpuId`, `GoodsStyleId`), factories (`SpuFactory`, `GoodsStyleFactory`), repositories (`SpuRepository`, `GoodsStyleRepository`), status/state machine (`CommodityStatus`), and error types (`CommodityErrors`). A separate `snapshot/` subpackage holds read-model snapshots (`SpuSnapshot`) and its repository for query-side isolation. Draft editing is modeled as a copy-on-write flow: an ON_SALE SPU can produce a DRAFT copy via `createDraftCopy`, which merges back into the source through `mergeFromDraft`.
- `domain/inventory`: implements TCC-style stock management (`Inventory` with reserve/deduct/release/add), concurrency control via `InventoryLock`, and idempotent `ReservationRecord` tracking.
- `service/`: application services (`CommodityService`, `InventoryService`) orchestrate domain objects, persist via repositories, publish domain events through `DomainEventPublisher`, and implement the external API contract (`GoodsSnapshotQueryService`). Event handlers (`AfterSaleStockRestoreEventHandler`, `InventoryConfirmEventHandler`, `InventoryReleaseEventHandler`) react to cross-context events.
- `acl/`: anti-corruption layer exposing interfaces like `OssService` for infrastructure concerns; event DTOs (`*RequestedEvent.kt`) bridge inbound messages from other contexts.

Dependency direction is strict: `service` → `domain` → `acl`; tests mirror this structure under `src/test/kotlin`. The module depends on shared abstractions in `:j-store-common-core` (Result, Entity, AgreeGate, DomainEventPublisher) and exposes API contracts via `:j-store-goods-api`.
