The module follows a strict DDD layering under `com.jstore.order`:
- `domain/order` and `domain/aftersale`: two aggregates each exposing an interface (`Order`, `AfterSale`) that extends `AgreeGate<T>` from `j-store-common-core`, plus an `*Impl` class holding mutable state, a `*Factory` for creation/validation, value objects (status enums, IDs, info DTOs), and a repository interface. Each aggregate maintains its own `DomainEvent` queue via `getDomainEvent()`.
- `service`: application-layer orchestrators (`OrderService`, `AfterSaleApplicationService`) that load aggregates through repositories, delegate all business rules to domain methods, persist changes, and publish domain events via `DomainEventPublisher`. They also implement idempotency for after-sale commands using SHA-256 digests of command payloads.
- `acl`: anti-corruption layer defining external contracts (`GoodsService`, `AfterSaleMerchantResolver`) and explicit cross-context events (`OrderStockConfirmedEvent`, `OrderStockInsufficientEvent`) annotated with `@DomainEventType` and implementing `ExplicitDomainEvent`.
- Event handlers (`OrderStockEventHandler`, `OrderStockInsufficientEventHandler`, `OrderRefundProjectionHandler`) consume these ACL events and drive order state transitions.
Dependency direction is one-way: service → domain; acl depends on neither; tests mirror the source tree under `src/test/kotlin`.
