- Each aggregate exposes an interface extending `AgreeGate<T>` with a separate `*Impl` class that holds private mutable fields and exposes them as read-only getters, keeping state encapsulated behind the interface.
- All mutating domain operations return `Result<Unit, BusinessError>` and use a private `transition(valid, operation, action)` helper in implementations to enforce preconditions before applying state changes and publishing events.
- Application services follow a uniform pattern: validate CMD via `cmd.validate()`, load aggregate from repository, call a single domain method, save via repository, then iterate `order.getDomainEvent()` to publish each event through `DomainEventPublisher`.
- Cross-boundary integration uses the ACL pattern: external contracts are defined as interfaces (`GoodsService`, `AfterSaleMerchantResolver`) and cross-context signals are modeled as data classes implementing `ExplicitDomainEvent` with `@DomainEventType` annotations.
- Idempotency for after-sale commands is enforced by computing a SHA-256 hash of the command payload and checking a receipt table before executing, returning `IDEMPOTENCY_CONFLICT` when hashes differ.
- Domain events are emitted only inside aggregate methods via `publishEvent(...)` and collected in a `Queue<DomainEvent>` exposed through `getDomainEvent()`, never published directly from application code.
