The module follows a clean DDD layering within `com.jstore.user`:
- `domain/useraccount/` holds the aggregate root (`UserAccount` interface + `UserAccountImpl` implementation), value objects (`Nickname`, `Password`, `UserId`, `AuthTokenPair`), domain events (`UserAccountRegisteredEvent`, `UserAccountLoggedInEvent`, `UserAccountForcedOfflineEvent`), and the `UserAccountFactory` / `UserAccountRepository` abstractions. State transitions are enforced by `UserAccountStatus`.
- `service/UserAccountService.kt` is the single application service that wires together `UserAccountFactory`, `UserAccountRepository`, `PasswordHasher`, `TokenProvider`, `TokenStore`, and `DomainEventPublisher` to orchestrate use cases (register, login, refreshToken, changeNickname, changePassword, disable, enable, forceOffline). It contains no business rules — all validation and state mutation is delegated to the aggregate.
- The aggregate exposes a `domainEventQueue` via `AgreeGate<UserId>` from `j-store-common-core`; events are published through the injected `DomainEventPublisher` after persistence.
- Dependency direction: service → domain interfaces; domain depends only on `j-store-common-core` (errors, properties, Result, SnowFlakSequence); tests mock all collaborators via Mockito-Kotlin and Kotest property-based tests cover value-object invariants.
