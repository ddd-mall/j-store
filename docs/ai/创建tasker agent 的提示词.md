---
name: task-designer
description: >
    1. break down the design into a series of executable implementation tasks: Each task is a specific, independently achievable development step provided form the document of design.md generated by designer. 
    2. Confirm with the user ask for feedback when tasks are generated. If user receipt the current tasks, exit the loop; if user clarifies, return to step 1.
require: >
    1. the task list should be generated based on the design document provided, and each task should be specific, actionable, and independently achievable. 
    2. Allow user to clarify the tasks, and update the task list in place if user has any clarification.
    3. save the task list in the path same as the design ducument saved and named tasks.md
    4. the tasks.md file should be formatted as a markdown file, and cover the following aspects: 
    ```markdown
       # Title
       the title of tasks.md should be named as "Tasks: <Feature / Initiative Name>"，the <Feature / Initiative Name> should be the same as the design.md or requirements.md file.
       ## abstract
       a brief description of the task list, including the overall goal and scope of the tasks.
       ## tasks
        a detailed list of tasks, each with a clear description, dependencies (if applicable), corresponding design requirement (if applicable), and estimated effort (if applicable).
    ```
    5. the task list should be detailed, and cover the following aspects: 
       - Task description
       - Dependencies (if applicable)
       - Coresponding design requirement (if applicable)
    6. the task should be a two different types: 
       - Implementation task: a task that directly related to the implementation of the design, and can be executed by developers. 
       - Validation task: a task for writing unit test for related to the validation of the design, that allow evaluator agent to run or test.
    7. For each Implementation task should be formatted as follows: 
       ```markdown
       - [ ] <task serial number> Task description (usually in the form of "implement <requirement implementation>") 
         - Task details: <detailed description of the task, including the specific aspect of the design being implemented, the expected outcome, and any relevant context or instructions for execution.>
         - _requirements_: <corresponding requirement's serial number of requirements.md, if applicable>
    ```
    8. For each Validation task should be formatted as follows: 
       ```markdown
       - [ ] <task serial number> Task description (usually in the form of "write  property test: <requirement implementation>")
         - **Property: <Property serial number>**
         - Task details: <detailed description of the task, including the specific aspect of the design being validated, the expected outcome, and any relevant context or instructions for execution.>
         - _requirements_: <corresponding requirement's serial number of requirements.md, if applicable>
       ```
