# 日志安全与字段规范

## 目标

本规范约束应用日志、任务日志、HTTP 访问日志和集成消息日志。日志用于诊断运行行为，不是业务载荷备份、审计账本或消息存储。

## 字段分级

| 分级 | 示例 | 规则 |
|---|---|---|
| 允许 | `service.name`、环境、版本、日志级别、`event.name`、状态、耗时、受控错误类型 | 可以直接记录 |
| 受控标识 | `trace_id`、`span_id`、`correlation_id`、`message_id`、订单 ID、任务 ID、租户 ID | 只作为结构化字段；不得拼接到自由文本或作为 Loki 高基数标签 |
| 必须脱敏 | 手机号、邮箱、收货人、地址、IP、设备标识 | 默认不记录；确有诊断需要时只记录经批准的不可逆摘要或最小掩码 |
| 禁止 | 密码、JWT、验证码、密钥、Cookie、Authorization header、支付敏感数据、完整请求体、任务或消息原始载荷 | 任何级别和环境都不得记录 |

## 通用要求

- 使用稳定事件名和显式键值字段，不依赖包含载荷对象的 `toString()`。
- 异常日志保留异常类型和堆栈，但异常消息、第三方响应和嵌套对象仍需经过敏感数据审查。
- HTTP 日志只记录方法、规范化路径、状态、耗时和关联标识；不记录 query、header、body 或认证令牌。
- 认证失败只记录受控错误码和关联标识，不记录用户提交的凭据。
- 集成消息日志只记录 envelope 元数据，不记录 payload。
- 定时任务日志只记录 `job_id`、`topic`、`slot`、状态和受控错误类型，不记录 `content`。
- 示例、测试、Dashboard 和运行手册只使用合成数据。

## 字段命名

公共字段遵循 ECS 语义与项目既有上下文约定：

- ECS 资源、事件、错误和 HTTP 字段使用点号层级，例如 `service.name`、`service.version`、`service.environment`、`event.name`、`event.outcome`、`error.type`、`error.code`、`http.response.status_code`
- 项目自定义关联上下文使用 snake_case
- `correlation_id`、`trace_id`、`span_id`
- `message_id`、`causation_id`、`transport_id`
- 非 ECS 的业务字段使用 snake_case，例如 `duration_ms`

业务标识使用领域名加 `_id`，例如 `order_id`、`job_id`。同一语义不得在不同模块中创建别名。

## 评审检查

新增或修改日志时必须检查：

1. 是否可以只记录标识和状态，而不记录对象或载荷。
2. 参数化日志是否会间接调用包含敏感字段的 `toString()`。
3. 异常消息是否可能包含请求、第三方响应或数据库内容。
4. MDC/日志作用域是否在成功、异常和线程复用路径可靠清理。
5. 新字段是否有稳定语义，是否会造成高基数索引或不必要的存储成本。

发现真实敏感数据进入日志时，应停止继续扩散，按安全事件处理并由授权人员执行后端删除或轮换；不得由自动化任务直接修改生产日志或凭据。
