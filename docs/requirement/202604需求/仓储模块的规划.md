# 仓储模块（Warehouse）规划

## 1. 模块定位：与 goods.inventory 的区别

| 维度 | goods.inventory（现有） | warehouse（新模块） |
|------|------------------------|---------------------|
| **关注点** | **可售库存**——"还能卖多少" | **实物库存**——"货在哪里、怎么流转" |
| **核心问题** | 库存预扣/扣减/释放（TCC） | 入库/出库/调拨/盘点/库位 |
| **粒度** | SKU 级别的数量 | SKU × 仓库 × 库位 × 批次 |
| **驱动方** | 订单流程驱动 | 仓储作业/WMS 操作驱动 |
| **时间语义** | 实时（下单瞬间） | 作业级（分钟~小时） |

**核心关系**：`goods.inventory` 是 **销售域的库存视图**，`warehouse` 是 **履约域的实物管理**。两者通过领域事件保持最终一致：

```
warehouse 入库完成 → 发事件 → goods.inventory.add(qty)
order 确认发货     → 发事件 → warehouse 创建出库单
warehouse 出库完成 → 发事件 → goods.inventory.deduct(qty)
盘点差异           → 发事件 → goods.inventory 校准
```

> **关键决策**：不把现有 Inventory 搬到 warehouse。它们属于不同限界上下文，保持各自的聚合根，通过事件同步。

## 2. 核心能力清单

```
┌─────────────────────────────────────────────────┐
│                 Warehouse Module                 │
├──────────────┬──────────────────────────────────┤
│  仓库管理     │ 仓库CRUD、库区/库位拓扑、启用/停用  │
│  入库管理     │ 采购入库、退货入库、调拨入库、上架   │
│  出库管理     │ 销售出库(拣货→打包→发货)、调拨出库  │
│  库内调拨     │ 同仓库位间移动                     │
│  跨仓调拨     │ 仓间转移(出库单+入库单配对)         │
│  库存盘点     │ 全盘/抽盘、差异处理、损溢调整       │
│  批次/效期    │ 批次追踪、先进先出、效期预警         │
│  库存查询     │ 实时库位库存、SKU汇总、仓库汇总     │
└──────────────┴──────────────────────────────────┘
```

**第一阶段**（优先）：仓库管理 + 入库 + 出库 + 库存查询  
**第二阶段**（后续迭代）：盘点 + 调拨

## 4. 核心领域模型设计

### 4.1 仓库管理子域

```kotlin
// ========== 聚合根 ==========
class Warehouse(
    val warehouseId: WarehouseId,          // 值对象
    var warehouseName: String,
    var warehouseCode: String,             // 业务编码, e.g. "WH-SHANGHAI-01"
    val merchantCode: String,              // 关联商家(与 shop 对齐)
    var address: WarehouseAddress,         // 值对象
    var status: WarehouseStatus,           // ACTIVE / INACTIVE
    val zones: MutableList<Zone> = mutableListOf()
) {
    fun addZone(zone: Zone)
    fun deactivate()                       // 校验：无库存时才能停用
}

// ========== 实体 (Warehouse 聚合内) ==========
class Zone(
    val zoneId: ZoneId,
    var zoneName: String,                  // e.g. "A区-常温"
    val zoneType: ZoneType,                // NORMAL / COLD_CHAIN / RETURNS
    val bins: MutableList<Bin> = mutableListOf()
) {
    fun addBin(bin: Bin)
}

class Bin(
    val binId: BinId,
    val binCode: String,                   // e.g. "A-01-03" (区-排-层)
    var capacity: Int,
    var status: BinStatus                  // AVAILABLE / FULL / DISABLED
)

// ========== 值对象 ==========
data class WarehouseId(val value: String)
data class ZoneId(val value: String)
data class BinId(val value: String)
data class WarehouseAddress(
    val province: String, val city: String,
    val district: String, val detail: String
)
enum class WarehouseStatus { ACTIVE, INACTIVE }
enum class ZoneType { NORMAL, COLD_CHAIN, RETURNS }
enum class BinStatus { AVAILABLE, FULL, DISABLED }
```

### 4.2 入库子域

```kotlin
// ========== 聚合根 ==========
class InboundOrder(
    val inboundOrderId: InboundOrderId,
    val inboundNo: String,                 // 业务单号 "IB202506120001"
    val warehouseId: WarehouseId,
    val inboundType: InboundType,          // PURCHASE / RETURN / TRANSFER_IN
    val merchantCode: String,
    var status: InboundStatus,             // CREATED → RECEIVING → SHELVING → COMPLETED
    val lines: MutableList<InboundLine> = mutableListOf(),
    val sourceOrderNo: String? = null      // 关联的采购单/退货单号
) {
    fun addLine(line: InboundLine)
    fun startReceiving()
    fun receiveLine(skuRef: SkuRef, actualQty: Int, batchNo: String?): ReceiveResult
    fun shelve(lineId: InboundLineId, binId: BinId, qty: Int)
    fun complete(): List<DomainEvent>      // 发布 InboundCompletedEvent

    // 不变量: 实收数量 ≤ 计划数量 * (1 + 超收容差)
}

// ========== 实体 ==========
class InboundLine(
    val lineId: InboundLineId,
    val skuRef: SkuRef,                    // ACL 值对象
    val expectedQty: Int,
    var receivedQty: Int = 0,
    var shelvedQty: Int = 0,
    var batchNo: String? = null
) {
    fun receive(qty: Int)
    fun shelve(qty: Int)
}

// ========== 值对象 ==========
data class InboundOrderId(val value: String)
data class InboundLineId(val value: String)
enum class InboundType { PURCHASE, RETURN, TRANSFER_IN }
enum class InboundStatus { CREATED, RECEIVING, SHELVING, COMPLETED, CANCELLED }
```

### 4.3 出库子域

class OutboundOrder(

### 4.4 仓库库存子域

```kotlin
// ========== 聚合根 ==========
// 核心：一个 SKU 在一个仓库一个库位的库存
class WarehouseStock(
    val stockId: WarehouseStockId,
    val warehouseId: WarehouseId,
    val binId: BinId,
    val skuRef: SkuRef,
    val batchNo: String?,
    var onHandQty: Int,                    // 实际在库
    var allocatedQty: Int,                 // 已分配未拣货
    var frozenQty: Int                     // 盘点冻结
) {
    val availableQty: Int                  // = onHandQty - allocatedQty - frozenQty
        get() = onHandQty - allocatedQty - frozenQty

    fun inbound(qty: Int)                  // 入库上架 → onHandQty += qty
    fun allocate(qty: Int)                 // 出库分配 → allocatedQty += qty
    fun pick(qty: Int)                     // 拣货确认 → onHandQty -= qty, allocatedQty -= qty
    fun freeze(qty: Int)                   // 盘点冻结
    fun adjust(delta: Int)                 // 盘点调整

    // 不变量: onHandQty >= 0, allocatedQty >= 0, availableQty >= 0
}

// ========== 实体: 库存流水(独立聚合) ==========
class StockMovement(
    val movementId: StockMovementId,
    val warehouseId: WarehouseId,
    val skuRef: SkuRef,
    val binId: BinId,
    val movementType: MovementType,        // INBOUND / OUTBOUND / ADJUST / TRANSFER
    val qty: Int,                          // 正=增, 负=减
    val referenceNo: String,               // 关联的入库单/出库单号
    val createdAt: Instant
)

enum class MovementType { INBOUND, OUTBOUND, ADJUST, TRANSFER }
```

## 5. 领域事件设计

### 5.1 仓储模块发出的事件

```kotlin
// 入库完成 → goods.inventory 增加可售库存
data class InboundCompletedEvent(
    val inboundNo: String,
    val warehouseId: String,
    val merchantCode: String,
    val items: List<InboundItem>           // skuId + qty
)

// 出库发货 → order 更新物流状态
data class OutboundShippedEvent(
    val outboundNo: String,
    val orderNo: String?,
    val trackingNo: String,
    val items: List<OutboundItem>
)

// 盘点调整 → goods.inventory 校准
data class StockAdjustedEvent(
    val warehouseId: String,
    val adjustments: List<AdjustmentItem>  // skuId + delta
)
```

### 5.2 仓储模块监听的事件

```kotlin
// 来自 order: 订单确认后需要创建出库单（复用现有 ACL 模式）
data class FulfillmentRequestedEvent(
    val orderId: String,
    val orderNo: String,
    val merchantCode: String,
    val items: List<FulfillmentItem>,      // skuId + qty
    val shippingAddress: ShippingAddress
)

// 来自 goods: SKU 信息变更 → 更新本地 SkuRef 缓存
data class SkuInfoChangedEvent(
    val skuId: String,
    val skuName: String,
    val barcode: String?
)
```

### 5.3 事件流转全景

```
order ──FulfillmentRequestedEvent──→ warehouse (创建OutboundOrder)
                                         │
                                    拣货→打包→发货
                                         │
warehouse ──OutboundShippedEvent──→ order (更新发货状态)
                                   ──→ goods.inventory (如需最终扣减校准)

采购系统/手工 ──→ warehouse (创建InboundOrder)
                      │
                  收货→上架
                      │
warehouse ──InboundCompletedEvent──→ goods.inventory.add(qty)
```

## 6. 与现有模块集成方式

### 6.1 与 goods 模块

| 方向 | 事件 | 效果 |
|------|------|------|
| warehouse → goods | `InboundCompletedEvent` | `InventoryService.add()` |
| warehouse → goods | `StockAdjustedEvent` | `InventoryService.adjust()` |
| goods → warehouse | `SkuInfoChangedEvent` | 更新本地 `SkuRef` |

**关键**：`goods.inventory` 保留为"可售库存"快照视图，`warehouse` 的库存是"实物真相"。

### 6.2 与 order 模块

```
现有流程(保持不变):
  order → StockReservationRequestedEvent → goods.inventory.reserve()

新增履约流程:
  order 支付完成后:
  order → FulfillmentRequestedEvent → warehouse.createOutboundOrder()

  warehouse 发货后:
  warehouse → OutboundShippedEvent → order.updateShipment()
```

> TCC 预扣流程不动，仍由 `goods.inventory` 处理。`warehouse` 只管实物流转。

### 6.3 与 shop 模块

通过 `merchantCode` 关联。仓库属于商家，查询时按 merchantCode 隔离。无直接事件通信。

### 6.4 集成模式总结

| 集成 | 方向 | 机制 | Spring Modulith |
|------|------|------|-----------------|
| order → warehouse | 异步事件 | `FulfillmentRequestedEvent` | `@ApplicationModuleListener` |
| warehouse → goods | 异步事件 | `InboundCompletedEvent` | `@ApplicationModuleListener` |
| warehouse → order | 异步事件 | `OutboundShippedEvent` | `@ApplicationModuleListener` |
| goods → warehouse | 异步事件 | `SkuInfoChangedEvent` | `@ApplicationModuleListener` |
| warehouse ↔ shop | 无直接通信 | 共享 merchantCode | — |

## 8. 关键设计决策

| 决策 | 推荐 | 理由 |
|------|------|------|
| Inventory 是否搬到 warehouse？ | **不搬** | 它是销售域概念，TCC 预扣逻辑与仓储无关 |
| WarehouseStock 聚合粒度？ | **SKU × 仓库 × 库位** | 支持库位管理，又不至于到批次级别太碎 |
| 入库/出库是否独立聚合？ | **是** | 生命周期独立，不与 WarehouseStock 放同一聚合 |
| StockMovement 独立聚合还是内嵌？ | **独立** | 流水只追加不修改，查询模式不同 |
| 与 order 的集成 | **异步事件** | 符合现有 ACL 模式，松耦合 |
| 第一阶段范围 | **仓库 + 入库 + 出库 + 库存** | 盘点/调拨是 V2 |

## 9. 实施建议

**最小行动路径**：
1. 创建 `j-store-warehouse` + `j-store-warehouse-infrastructure` 模块骨架
2. 实现 `Warehouse` 聚合根 + `WarehouseStock` 聚合根 + `InboundOrder` 聚合根
3. 打通 `InboundCompletedEvent` → `goods.inventory.add()` 事件链路
4. 链路验证完毕后，扩展出库流程（`OutboundOrder` + `FulfillmentRequestedEvent`）
5. 最后添加盘点和调拨
