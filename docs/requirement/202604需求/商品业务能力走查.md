# 走查

1. 缺少分类体系 (Category)
   主流电商的 SPU 一定挂在某个分类下，分类通常是树形结构（一级 → 二级 → 三级）。分类决定了：

前台导航和搜索筛选
该品类下有哪些规格属性模板（比如"服装"类目下才有"尺码"）
佣金费率、运费模板等运营规则
当前 SPU 没有 categoryId 字段，意味着无法按品类组织商品。

2. 缺少品牌 (Brand)
   主流电商 SPU 通常关联品牌。品牌是独立的值对象或实体，影响搜索、筛选、品牌馆等场景。当前模型没有品牌概念。

3. 属性体系过于简化
   当前 Attribute<String, String> 是纯自由文本 KV，没有区分：

属性类型	说明	当前支持
销售属性 (Sale Attribute)	决定 SKU 组合的属性，如颜色、尺码	✅ 但无约束
SPU 级属性 (Base Attribute)	不影响 SKU 的公共属性，如材质、产地、重量	❌
属性模板 / 属性组	由品类决定该 SPU 应该填哪些属性	❌
主流做法是品类绑定属性模板，创建 SPU 时根据模板校验必填属性，销售属性用于生成 SKU 矩阵。当前模型的属性完全自由填写，无法做结构化筛选和校验。

4. SKU 缺少关键字段
   当前 SKU 只有 skuName、attributes、price，缺少：

字段	说明
SKU 编码 (skuCode / barcode)	条形码或商家自定义编码，用于仓储和物流
重量 / 体积	运费计算依赖
SKU 图片	不同颜色对应不同主图
SKU 状态	单个 SKU 可独立启用/禁用，而非跟随 SPU 整体上下架
成本价	毛利计算
库存关联	当前库存用 CommodityCode 关联，但 SPU/SKU 与库存之间的映射关系不明确
5. 缺少商品图片和富文本详情
   当前 SPU 只有 name 和 description（纯文本 2000 字符），缺少：

主图列表 (mainImages)
详情页富文本 / 图文描述 (detailHtml / detailImages)
视频 (video)
这些在电商中是基础能力。

6. 缺少价格体系
   当前只有 SKU 单价，主流电商通常需要：

价格类型	说明
原价 (originalPrice)	划线价，用于展示折扣力度
销售价 (sellingPrice)	实际售价
会员价	不同会员等级不同价格
SPU 级价格区间	列表页展示 "¥99 - ¥199"
当前 SKU 只有一个 price，无法支持促销和多价格策略。

7. 缺少运费和物流相关信息
   没有运费模板关联、发货地、是否包邮等信息。这些通常在 SPU 级别配置。

8. 状态机偏简单
   三态 (DRAFT / OFF_SALE / ON_SALE) 覆盖了基本流程，但缺少：

审核状态：商家提交后需平台审核通过才能上架（多商户场景）
删除 / 归档：软删除或归档状态
预售状态：预售商品的特殊状态
9. 缺少多商户 (Seller / Shop) 支持
   当前 SPU 没有 sellerId 或 shopId，如果未来做平台型电商（多商户入驻），这是必须的。即使是自营，也建议预留。

10. 缺少 SPU 编码和搜索支持
    没有 spuCode（商品编号）、关键词 (keywords)、标签 (tags) 等用于搜索和运营的字段。

优先级建议
按对业务影响从高到低排序：

优先级	改进项	理由
P0	商品图片 + 富文本详情	没有图片的商品无法展示
P0	SKU 编码 + SKU 图片	仓储物流和前端展示的基础
P1	分类体系	商品组织和搜索筛选的基础
P1	价格体系 (原价/售价)	促销和价格展示的基础
P1	SKU 与库存的明确关联	当前 CommodityCode 和 SkuId 的关系不清晰
P2	品牌	搜索筛选和品牌运营
P2	属性模板 (品类绑定)	结构化属性管理
P2	运费模板	下单时运费计算
P3	审核流程	多商户场景
P3	多商户支持	平台化扩展
