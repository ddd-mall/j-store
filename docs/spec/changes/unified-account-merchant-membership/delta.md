# 统一账号与商户成员关系变更

## MODIFIED

### 身份账号定位

现有 `.kiro/specs/user-account` 中仅面向 C 端消费者的 `UserAccount`，调整为平台全局自然人身份。账号继续负责手机号、密码、状态和登录会话，不使用 `userType` 区分买家与商家。

同一个 `UserId` 可以作为买家下单，也可以通过商户成员关系参与一个或多个商户的经营。

### B 端资源授权

现有 B 端接口以 `currentUserId == merchantId` 判断权限的行为，修改为根据 `merchantId + userId` 加载有效成员关系，并校验当前操作所需权限。

未获得商户权限的调用继续按资源不存在处理，避免泄露其他商户资源。

## ADDED

### 商户与成员

- 系统必须持久化独立于 `UserId` 的 `MerchantId`。
- 一个商户可以包含多个成员；一个用户可以加入多个商户。
- 成员可以拥有多个商户作用域角色，角色映射为明确权限。
- 已禁用商户或已禁用成员不能获得任何商户权限。
- 创建商户的用户自动成为 OWNER。
- 只有具备成员管理权限的成员可以新增成员、调整非 OWNER 成员角色或禁用非 OWNER 成员。

### 严格新建

迁移只建立新商户模型，不从商品、订单、售后、支付或履约记录推导商户，不建立 `user_id = merchant_id` 的成员关系。所有商户及初始 OWNER 必须通过显式创建用例产生，所有商户业务资源必须引用真实存在的 `MerchantId`。

## REMOVED

- B 端资源不再把 `UserId` 与 `MerchantId` 数值相等视为授权依据。
- 删除按 actor 数值同时匹配买家和商户的售后查询入口。
- 删除 `merchants.owner_user_id`；OWNER 成员角色是商户所有权的唯一事实源。
- 不引入全局 `C`/`B` 单值账号类型；该模型无法表达同一用户同时买卖或管理多个商户。

## 范围外

- 平台内部管理员独立身份域、强制 MFA 和独立签发者。
- C/B 门户专属 OAuth Client、JWT `aud` 和登录页。
- 企业 SSO、邀请邮件、手机号查找成员和商户主体资质审核。
