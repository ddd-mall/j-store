# 统一账号与商户成员关系需求

## 目标

建立全新的“一套自然人身份 + 商户成员关系”账号模型，让同一用户既可作为买家，也可参与一个或多个商户经营，并彻底移除用户 ID 与商户 ID 数值相等的旧模型。

## 验收标准

1. 注册和登录返回全局 `UserId`，不提供 C/B 账号类型。
2. 创建商户后，创建者必须拥有该商户 OWNER 成员关系和全部商户权限。
3. 一个用户加入多个商户时，各商户角色和权限必须相互隔离。
4. 非成员、禁用成员或禁用商户访问 B 端资源时必须被拒绝。
5. ORDER_MANAGER 可以读取订单、审核售后并管理履约，但不能管理支付或成员。
6. FINANCE 可以读取和处理支付，但不能管理履约、商品或成员。
7. 只有具备 `MEMBER_MANAGE` 权限的成员可以新增成员、调整角色和禁用成员。
8. OWNER 成员不能通过普通成员管理接口被降权或禁用。
9. 支付、履约、商家售后接口必须通过成员权限授权，不再比较用户 ID 和商户 ID。
10. 数据库不得根据已有业务数据推导商户或 OWNER；商户及初始 OWNER 必须通过显式创建用例产生。
11. 数据库必须阻止同一用户在同一商户下出现重复成员关系或重复角色。
12. 商品、订单、售后、支付和履约中的 `merchant_id` 必须引用真实存在的商户。

## 质量目标

- 安全：授权默认拒绝，权限作用域必须包含商户 ID。
- 数据完整性：商户归属只有成员角色一个事实源，商户表不重复保存 owner 用户。
- 破坏性收敛：仅支持全新数据库；旧开发数据和旧应用版本不属于迁移或回滚目标。
- 可维护：领域模块不依赖 Spring/JPA；持久化实现位于 infrastructure 模块。
