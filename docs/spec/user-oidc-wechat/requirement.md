# 用户中心 OAuth 2.0 / OIDC 与微信网站扫码登录需求

## 状态与意图来源

状态：2026-11-08 用户确认按本规格方向实施；本地候选已实现，整体安全与真实平台验收尚未通过，见 [summary](summary.md)。

2026-11-08 用户明确要求建设 OAuth 2.0 + OIDC 并接入微信登录，并已确认：

1. 用户中心作为统一身份提供方，为本项目各端及授权应用签发令牌。
2. 微信渠道为微信开放平台的网站扫码登录。
3. 首次扫码未绑定本地账号时，先验证手机号，再创建或绑定本地账号。

用户在审阅规格后明确回复“按照这个方向修改”，本规格及 [delta](delta.md) 作为本次实现目标；代码安全审查和发布授权仍独立处理。

## 目标与边界

User / Authentication 继续拥有当前认证域的账号、已验证手机号和认证事实。微信只是外部身份来源，不成为业务系统的令牌签发者。微信登录和本地密码登录最终获得同一套本地账号身份及 OIDC 授权流程。

本次交付包括授权服务器、最小服务端登录/同意/手机号绑定页面、微信网站适配器、持久化、认证 SDK 接入、配置文档及自动化验证。页面仅服务认证流程；不建设消费者商城或商户门户前端。

## 验收标准

### AUTH-1 标准协议与客户端

1. 提供 OAuth Authorization Code + PKCE S256；所有客户端都要求 PKCE。禁用 implicit、password、自定义微信 code 换本地 token grant、device grant、client credentials 和动态客户端注册。
2. 提供 OIDC discovery、JWKS、ID Token、UserInfo、撤销、introspection 和 RP 发起登出能力。Discovery 只声明实际启用的能力。
3. 客户端由受控配置预注册，明确 public/confidential、精确 redirect URI、允许 scope、资源 audience 和登出返回 URI。未注册客户端、通配回调、非法 scope、非法 audience 均拒绝。
4. Confidential 客户端通过 `client_secret_basic` 验证，secret 仅保存密码摘要。Public 客户端不配置 secret，也不签发 Refresh Token；需要持续登录的浏览器应用使用 confidential BFF。
5. 初始 scope 为 `openid`、`profile`、`phone`、`offline_access`；`profile` 只开放本地昵称，`phone` 只开放已验证手机号，`offline_access` 仅供显式获准的 confidential 客户端使用。资源权限不从这些身份 scope 推导。
6. 用户可以查看客户端和请求资料范围并同意或拒绝。拒绝不签发授权码；已有同意不能绕过账号状态、当前会话或客户端配置校验。尊重 `prompt=login/none/consent` 和 `max_age`，返回标准错误。

### AUTH-2 令牌、认证域与会话

1. `iss` 为部署显式配置且稳定的 HTTPS 地址，不能从任意 Host 或转发头推导；`sub` 为当前域内稳定 `UserId` 字符串。微信 openid/unionid 不进入业务主标识。
2. ID Token 的 audience 为 client ID；Access Token 的 audience 为明确允许的业务资源。业务 API 不接受 ID Token、Refresh Token 或微信 token 作为 Bearer Access Token。
3. Access Token 使用非对称签名并带 `kid`、`iss`、`sub`、`aud`、`iat`、`exp`、`jti`、`sid` 和会话撤销代次；ID Token 校验所请求的 `nonce`，返回适当的 `auth_time`。JWKS 只公开公钥。
4. 默认授权码有效期 60 秒、Access Token 15 分钟、ID Token 5 分钟、Refresh family 绝对有效期 7 天、浏览器登录会话空闲期 30 分钟且绝对不超过 12 小时。测试使用可注入时钟。
5. 授权码绑定 client、redirect URI、PKCE、scope、账号和认证会话，原子单次使用。过期、错客户端、错 verifier、重复或并发兑换不得产生两个有效授权。
6. Refresh Token 为高熵随机值，服务端只保存不可逆摘要；每次刷新轮换，校验 client、账号、授权和会话，禁止扩大 scope。并发最多一个成功；旧值重放撤销整个 family 及其 Access Token。保留必要的旧摘要至 family 到期，以识别重放。
7. 改密、禁用和强制下线立即使全部浏览器会话、未兑换授权码、Access Token 和 Refresh family 失效；普通登出撤销当前登录会话及其派生授权。重新启用账号不能恢复旧会话。
8. 每次业务请求通过 SDK 的 `AccessTokenVerifier` 校验签名、算法、kid、issuer、audience、有效期、令牌用途和服务端撤销状态。撤销依赖不可用时默认拒绝，不降级为仅验签。
9. 未请求或未同意 `phone` 时，ID Token、UserInfo 和公开 discovery 均不暴露手机号；任何 token 不携带商户角色或平台管理权限。商户权限继续由 Shop 成员关系判定。

### WX-1 微信扫码与回调

1. 登录页提供微信网站扫码入口；应用 ID、secret 和回调地址由服务端配置。浏览器不提交外部用户 ID、微信 access token 或 app secret 作为身份证明。
2. 服务端生成不少于 128 位随机 `state`，绑定发起浏览器、登录意图及服务端保存的授权请求，5 分钟过期且原子单次消费。缺失、错误、过期、重放或跨浏览器回调均失败。
3. 微信 code 仅由服务端向固定 HTTPS 微信端点兑换；拒绝授权、无 code、上游错误、超时、无效响应或外部身份不一致时，不创建账号、不建立登录状态、不签发本地令牌。
4. 校验成功后，以 `provider + appId + openid` 查询本地绑定。已绑定 ACTIVE 账号可以进入标准授权流程；禁用账号拒绝登录。
5. 微信 access/refresh token、secret、code 不返回给业务客户端，也不长期保存；日志、trace、异常与访问日志必须屏蔽相关查询参数。

### WX-2 首次绑定与账号创建

1. 未绑定身份只产生与当前浏览器、微信身份和原授权请求绑定的短期 onboarding 状态；在完成手机号验证前不得签发本地登录会话、授权码或业务令牌。
2. 手机号挑战必须区分注册/微信绑定用途并绑定 onboarding 意图；有效期、尝试次数与发送速率受控，原子消费且不可在别的流程重复使用。
3. 手机号已有 ACTIVE 账号时，页面明确告知本次将绑定该账号，经用户提交确认并验证手机号后绑定到该账号；不创建第二个账号，也不要求使用微信昵称覆盖本地资料。
4. 手机号未注册时，用户提供符合现有规则的昵称和新密码，验证手机号后原子创建本地账号及微信绑定；保留现有账号手机号和密码不为空的不变量，不伪造手机号或密码。
5. 外部身份只能绑定一个账号；同一账号在同一微信 app 下只能绑定一个微信身份。手机号并发注册、重复提交和竞争绑定由数据库唯一约束及事务兜底，不发生静默换绑。
6. 已绑定另一微信身份、账号禁用、证据过期或并发冲突时，返回受控失败并重新发起流程；不得合并账号、覆盖绑定或跳过手机号验证。
7. `unionid` 只作为当前开放平台范围内的可选附加标识；缺失时仍可登录，本次不据此自动合并账号或跨 app 建立新绑定。
8. onboarding 有效期 10 分钟，成功后单次消费；超时或提交失败允许安全重启。上游 HTTP 调用不持有本地数据库写事务，回滚不得留下可登录的半成品绑定。

### OPS-1 配置与运行

1. OAuth 授权、客户端配置和用户同意必须持久化；浏览器会话及临时 state 可使用共享 Redis，支持多实例且进程重启不意外恢复已撤销权限。
2. 生产启用要求显式 issuer、签名私钥、客户端配置、Redis、短信适配器；启用微信还要求 appId、secret、固定 HTTPS 回调。缺配置启动失败，禁止内存授权存储或临时生成的生产密钥兜底。
3. 提供受 Profile 限制的开发方式及微信假服务测试；假服务不得出现在生产装配中。真实微信联调单独记录证据，自动化假服务通过不能标为真实平台验收。
4. 私钥、client secret、微信 secret 和真实短信验证码不进入 Git；文档使用占位符。签名支持 active kid 和验证期保留旧公钥，移除旧 key 必须覆盖既有令牌有效窗口。

## 质量目标与范围外

- 安全：登录态固定攻击、CSRF、开放重定向、授权码重放、Refresh 重放、登录意图混淆及并发绑定均有反例测试；Cookie 为 HttpOnly、生产 Secure，并按回调方式选择 SameSite。
- 一致性：账号创建与绑定同一数据库事务；数据库和 Redis 不伪装成一个原子事务，失败最多造成额外重新登录，不能放宽撤销。
- 可维护：协议细节由成熟框架处理，领域和应用层保持无 Spring/JPA 依赖；账号、授权、会话与外部身份各有明确职责。
- 范围外：小程序、公众号、App SDK、跨域账号合并、解绑/换绑、自动 UnionID 合并、平台管理员身份域、MFA、第三方开发者门户与动态注册。本次不包含生产部署、真实密钥操作或微信平台配置写入。
