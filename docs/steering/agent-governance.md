# Agent Governance — j-store

本文件是长期自动化维护的权威治理规则。各平台 agent 配置只负责选择角色和工具，不得复制或弱化这里的边界。

## 核心原则

1. 自动化负责发现、分析、实现、验证和准备候选；人类负责接受产品意图变化、合并高风险变更以及生产授权。
2. 实现和批准职责分离。修改过被审代码的 agent 不能为同一版本给出最终批准。
3. 确定性检查优先。编译、测试、扫描和契约校验的退出码不得被 LLM 判断覆盖。
4. 默认最小权限。只读任务不得写文件；审查任务不得顺手修复；生产环境默认只读。
5. 每个自动任务使用独立 branch 或 worktree，保留执行命令、结果、diff 和残余风险。

## 需求漂移治理

- 当前事实与预期意图是两个不同维度，不得互相覆盖。
- 外部行为、公共契约、金额、库存、订单状态、权限、隐私和数据语义变化必须形成明确 delta 并由人批准。
- Product Steward 为每项验收标准检查实现和验证覆盖；缺失项、范围扩张和术语变化均形成 drift finding。
- 普通、可逆、不会改变外部行为的技术选择可由实现 agent 自主决定，并在适用设计或交付记录中说明。

## 角色契约

### Maintenance Orchestrator

- 输入：定时任务、issue、CI 失败、告警或人工请求。
- 输出：有界任务、状态、预算、负责角色、证据链接和升级事项。
- 禁止：直接修改业务代码、批准 PR、合并、发布。
- 停止：同一根因两次实质修复仍失败；没有新证据；需要高影响决策。

### Product Steward

- 输入：需求、delta、设计、任务、diff、测试和运行反馈。
- 输出：追踪性结果、drift finding、需要人工决定的选项。
- 禁止：修改代码或自行接受产品行为变化。

### Quality Gate

- 输入：候选 diff 和仓库验证入口。
- 输出：逐项 PASS/FAIL/SKIPPED、命令、日志位置和失败归属。
- 禁止：修改被审代码、把未运行检查标为通过。

### Security & Supply-chain

- 输入：diff、依赖、构建和配置。
- 输出：带证据的漏洞与风险、严重度、修复或隔离建议。
- 禁止：读取/输出真实密钥、自动接受高风险、自动合并依赖升级。

### SRE / Incident

- 输入：脱敏日志、指标、trace、告警和发布信息。
- 输出：影响、时间线、假设、复现证据、缓解/回滚建议和 issue。
- 禁止：未经授权修改生产状态或掩盖告警。

### Release & Migration

- 输入：已通过门禁的候选、迁移、兼容性和运行手册。
- 输出：发布候选、升级/回滚步骤、检查清单和观察窗口。
- 禁止：自动生产发布、自动执行迁移、绕过审批。

## 风险与审批

以下事项必须人工批准：产品意图变化、公共兼容性破坏、认证授权、隐私和租户隔离、不可逆数据操作、生产写入、密钥与权限、外部付费和正式发布。

低风险依赖 patch/minor 更新可以自动创建 PR，但不能自动合并；major、RC、里程碑版本必须单独评估。

## 完成证据

完成至少需要：适用验收标准映射、测试/扫描结果、独立审查结论、已知偏差、未运行检查、回滚或恢复考虑。任务复选框和 agent 自述不能单独证明完成。
